RCA B4 : Acceptation incorrecte d'un code promotionnel expiré

Symptôme observé



Le code promotionnel EXPIRED, dont la date de validité est dépassée, est accepté par l'application au lieu d'être rejeté.



L'utilisateur peut poursuivre sa commande et accéder à la page de paiement sans recevoir le message d'erreur attendu : « Promo code expired ».



Impact (pour l'utilisateur, pour l'entreprise)



Pour l'utilisateur :



L'application ne signale pas qu'un code promotionnel est expiré.

L'utilisateur peut finaliser une commande avec une réduction qui ne devrait plus être applicable.



Pour l'entreprise :



Application injustifiée de réductions commerciales.

* Risque de perte financière.
* Diminution de la fiabilité du système de réservation et de paiement.

Preuves

* Test UI : test\_expired\_promo\_code\_shows\_error échoue.

&#x20;  Résultat UI : la page de paiement s'affiche au lieu du message « Promo code expired ».

* Test API : test\_rm4\_promo\_codes\[EXPIRED] renvoie HTTP 201 au lieu du code attendu HTTP 400.
* Base de données : le code EXPIRED présente une remise de 15 % et une date d'expiration au 25/10/2026.
* Code source : backend/app/routers/orders.py, ligne 34, fonction \_validate\_promo().



&#x20;5 Pourquoi



Pourquoi	Réponse	    Preuve

1\. Pourquoi le test UI échoue-t-il ?	Le message d'erreur indiquant l'expiration du code promotionnel ne s'affiche pas.	Échec du test Playwright test\_expired\_promo\_code\_shows\_error.

2\. Pourquoi le message d'erreur ne s'affiche-t-il pas ?	L'API accepte le code promotionnel expiré et crée la commande.	Le test API reçoit HTTP 201 au lieu de HTTP 400.

3\. Pourquoi l'API accepte-t-elle ce code ?	La vérification de la date d'expiration est désactivée lorsque le mode bug est activé.	Condition présente à la ligne 34 de orders.py.

4\. Pourquoi la vérification est-elle désactivée ?	La condition de rejet dépend du paramètre not settings.seed\_bugs.	Analyse de la fonction \_validate\_promo().

5\. Pourquoi ce défaut peut-il passer les contrôles qualité ?	Les tests et le pipeline CI doivent garantir que les règles métier restent vérifiées et que les échecs des tests UI bloquent la validation du code.	Tests API/UI et configuration de .github/workflows/ci.yml à examiner.



Cause racine



La cause racine est une condition de validation incorrectement désactivée en mode bug.



Dans backend/app/routers/orders.py, ligne 34, le rejet d'un code promotionnel expiré dépend de la condition not settings.seed\_bugs.



Lorsque SEED\_BUGS=true, cette condition empêche l'exécution du rejet HTTP 400. L'API accepte alors le code expiré et autorise la création de la commande.



Actions correctives



Produit :

Garantir le rejet systématique des codes promotionnels expirés en production.

Retourner une erreur HTTP 400 avec le message « Promo code expired ».

Ajouter une validation fiable de la date d'expiration.



Processus de test :



Maintenir un test API vérifiant le rejet des codes expirés.

Maintenir un test UI vérifiant l'affichage du message d'erreur.

Intégrer ces tests dans le pipeline CI.

Empêcher la validation d'une modification lorsque les tests échouent.



Comment vérifier que c'est corrigé

Exécuter le test API test\_rm4\_promo\_codes\[EXPIRED] et vérifier que le résultat est HTTP 400.

Exécuter le test UI test\_expired\_promo\_code\_shows\_error et vérifier que le message « Promo code expired » apparaît.

Vérifier qu'un code promotionnel valide reste accepté.

Exécuter l'ensemble des tests concernés.

Vérifier que le pipeline CI échoue lorsqu'un test de régression échoue.
